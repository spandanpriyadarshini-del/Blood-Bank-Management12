Abstract

The Blood Bank Management System replaces paper registers with a small web application backed by a relational database. It records donated blood units, registers hospital requests, issues stock using the earliest-expiry-first rule, and raises expiry and shortage alerts. The earlier console project stored data in text files; this version moves the data into SQLite so that keys and constraints keep it consistent.

Introduction

UI

Single-page HTML, CSS and vanilla JavaScript with tabs, forms and tables.

Database

SQLite with 6 related tables.

Language

Python 3 (standard library) for the server; JavaScript in the browser; SQL for data.

Objective

  • Keep an accurate, searchable record of every blood unit and its donor.
  • Reduce wastage by issuing units that expire first.
  • Track hospital requests from PENDING to PROCESSED or CANCELLED.
  • Warn about expiring stock and groups running low.
  • Demonstrate joins, constraints, keys and CRUD in a real project.

Concepts used

Keys

PRIMARY KEY uniquely identifies each row; FOREIGN KEYs link tables.

unit_id TEXT PRIMARY KEY,
donor_id INTEGER REFERENCES donors(donor_id)

Constraints

NOT NULL, UNIQUE, DEFAULT and CHECK keep bad data out.

quantity INTEGER CHECK(quantity > 0),
blood_group TEXT CHECK(blood_group IN ('A+',...)),
status TEXT DEFAULT 'AVAILABLE'

Joins

Combine rows from related tables.

SELECT u.unit_id, d.name, u.expiry
FROM blood_units u
JOIN donors d ON d.donor_id = u.donor_id;
